The test above reads the text of `Cargo.toml`. It does not show what cargo did. `scripts/check.sh app` forces a rebuild (`cargo clean -p interlo-desktop --release`, then `cargo build --release -p interlo-desktop -v`) and keeps the `rustc` command lines of the crate in `docs/m0/M0b-01/evidence/01-build-flags.txt`:

```text

binary size (stat -f %z target/release/interlo-desktop): 5897168 bytes
RESULT: 2 rustc commands (lib bin) have opt-level=3, codegen-units=1, a strip flag, no panic flag; the bin has lto=thin; no profile or rustflags override found
```

The flags assertion can fail: `05-negative-controls.txt` shows it refusing the real command line with `-C opt-level=1`, `-C codegen-units=16`, `-C lto=off`, no strip flag and `-C panic=abort`, and the override guard refusing `CARGO_PROFILE_RELEASE_OPT_LEVEL=1` in the environment. These controls change one flag of the real line: a real build with a wrong profile would rebuild the whole dependency tree. The guard also checks `.cargo/config*` files above the repository and in `CARGO_HOME` for a profile or `rustflags`.

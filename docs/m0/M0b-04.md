# M0b-04: Vietnamese input in a text field of the desktop shell

Result: **BLOCKED**, not a pass. On 2026-11-23 the owner stopped synthetic key events (no key or mouse event, no input source change, no clipboard change). AC-9 and AC-10 stay open until the owner allows the step again.

## What AC-9 asks for (changed by the owner on 2026-11-20)

The assistant types the Telex spelling of "Hôm nay mình rảnh, cũng gặp nhau ở quán bạn nhé." into the note field of the Workspace screen with real key events, through the built-in macOS Vietnamese (Telex) input source `com.apple.inputmethod.VietnameseIM.VietnameseTelex`. The text copied out of the field (Cmd+A, Cmd+C, `pbpaste`) must equal the sentence in Unicode form NFC; `diff` must print nothing. A negative control types the same keys with one wrong tone key and the diff must report the difference.

Keys sent: `Hoom nay minhf ranhr, cungx gawpj nhau owr quans banj nhes.` (key delay 120 ms).

The step is `scripts/app-check.sh telex`. It is opt-in and off by default: `scripts/check.sh app --typing`. It prints a notice before it starts, because it changes the input source and the clipboard for about a minute. SIGINT and SIGTERM restore both and end the step; SIGKILL cannot be trapped, and the log then holds the recovery commands.

## What happened on 2026-11-20

- One standalone run of the step printed `RESULT: PASS (AC-9)` (`raw diff exit: 0`, `NFC diff exit: 0`), detected the wrong-tone control and restored the input source and the clipboard. The next run overwrote its raw log, so there is no file for it. A claim without a file is not evidence, and this note does not count it as a pass.
- Two later runs ended `RESULT: NO`. The log of the last one is kept in `docs/m0/M0b-01/typing-attempts-2026-11-20/07-telex-typing.log`. The typing stopped several times because another app took the front (the log shows "stopping: the app ... is not in front"); the input method composes only while the app is in front. In the last attempt the copy did not reach the clipboard (the file shows the clipboard marker, not the field text). These runs say nothing about the input method or the app: the failure is the test setup under contention. AC-10's "wrong output" is therefore not recorded as a finding about the app.

## What a pass will prove, and what it will not

A pass proves that the web view takes the characters that the macOS Telex input method produces from key events. It does not prove typing with a third-party input method, or typing by hand.

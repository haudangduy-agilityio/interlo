## The scripted version (opt-in, not run in this pull request)

`scripts/app-check.sh telex` types the Telex spelling of the sentence with synthetic key events through the built-in macOS Telex input source (`com.apple.inputmethod.VietnameseIM.VietnameseTelex`), copies the field, compares it as NFC and runs a negative control with one wrong tone key. It stays opt-in: `scripts/check.sh app --typing`. It was not run in this pull request, so it adds no evidence here.

What a run of it would prove: the web view takes the characters that the macOS Telex input method produces from key events. What it would not prove: typing with a third-party input method, or typing by hand.

How it behaves, for whoever runs it: it needs Accessibility for the app that runs it and the Telex input source enabled; it prints a notice first, because it changes the input source and the clipboard for about a minute; keys go to the app's pid only; SIGINT and SIGTERM restore the input source and the clipboard text, and SIGKILL cannot be trapped (the log holds the recovery commands). Only the clipboard text is restored: do not run it with a secret copied.
